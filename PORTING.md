# Porting & validating a Toolathlon task on Harbor (v2 — fidelity contract)

**Contract: the Harbor version and official Toolathlon must have the exact
same verifier and the exact same initial environment. The only sanctioned
difference is the service backend — real service vs mock. The underlying
nature of the task must be identical.** When a fidelity gap is unavoidable,
surface it explicitly in the task's report — never silently accept it.

How the contract is implemented (see tools/port_task.py):

| upstream (official) | harbor port (v2) |
|---|---|
| task container = lockon0927/toolathlon-task-image | same image, via `toolathlon-harbor-base:v2` |
| graders/preprocess run `uv run -m tasks.finalpool.<t>...` in uv-synced repo env | identical: vendored pyproject+uv.lock uv-synced at /opt/toolathlon |
| initialize_workspace at run start: copy initial_workspace → preprocess(launch_time=now) → MCP dirs | identical, via ENTRYPOINT init.sh; healthcheck gates the agent on /var/run/toolathlon/ready |
| evaluation/ + groundtruth hidden from agent (artifact guard) | evaluation/ + groundtruth excluded from image; ship only in tests/ (post-agent) and solution/ (oracle-only) |
| grader args: --agent_workspace --groundtruth_workspace --res_log_file --launch_time | identical; launch_time = the runtime value init.sh recorded |

## Layout (generated by tools/port_task.py; regenerate with --force, it preserves solution/)

```
datasets/toolathlon/<task>/
  task.toml                 # schema 1.3; healthcheck gate; artifacts=["/app"]
  instruction.md            # /app preamble + upstream docs/task.md (placeholders resolved)
  environment/
    Dockerfile              # FROM toolathlon-harbor-base:v2
    task/                   # upstream task subtree MINUS evaluation/ + groundtruth_workspace/
    init.sh                 # runtime initialize_workspace equivalent
  tests/
    test.sh                 # uv-run upstream grader verbatim → reward.txt
    pkg/tasks/finalpool/<task>/   # full upstream task dir (grader + groundtruth + fixtures)
  solution/                 # oracle solution (finish by hand) + groundtruth copy
```

## Invariants

1. **Never modify grader OR preprocess logic.** Path/env fixes belong in
   test.sh / task.toml / init.sh. A genuinely unrunnable upstream bug:
   document, don't patch silently.
2. Groundtruth and evaluation code must never be reachable from the agent's
   image.
3. Missing runtime deps indicate a gap vs the official env — investigate why
   (the official image + uv env should already have everything upstream had).
   Never "fix" by changing what the grader checks.
4. Graders that READ --res_log_file (the port generator warns): audit that {}
   is semantically safe (grader treats it as "no trajectory info" without
   changing pass/fail semantics for a complete workspace). If the grader
   genuinely grades trajectory content, the task needs a trajectory bridge —
   flag it, don't fake it.

## Which services may be mocked

A mock is only fair when the task's interaction with the service is
**bounded**: the agent reads or writes account state whose contents the
seed fully determines.

| interaction | track | why |
|---|---|---|
| private/mutable account state (Notion pages, a WooCommerce store, a GCP project, a mailbox, your own HF or GitHub repo) | **mock** | the seed *is* the state; nothing outside it exists upstream either |
| open-ended lookup over public content (arXiv/Scholar search, web search, "the most downloaded X on the Hub", GitHub repo search, map directions to an arbitrary address, a YouTube playlist) | **live** | the query space cannot be enumerated. An agent that searches `attention is all you need` where the seed indexed `transformer` would fail a task it actually solved — the mock, not the agent, decided the outcome |
| public content named explicitly by the task (a specific dataset, a specific paper) | judgement | bounded in principle, but only mock it if the seed carries the *whole* object the grader compares; otherwise live |

Redirection is per host, so a single task can mix the two: `dataset-license-issue`
reads issues from a mocked `api.github.com` while its Hub license lookup goes
to the real `huggingface.co`.

Rollouts are part of this check, not just a score: a model transcript that
fails because the mock lacked an obvious query is the signal that the task
was mocked at the wrong boundary.

## Validation protocol (required for "ported" status)

```
.venv/bin/harbor run -p datasets/toolathlon/<task> -a oracle --job-name <task>-oracle
.venv/bin/harbor run -p datasets/toolathlon/<task> -a nop --job-name <task>-nop
```
- oracle → 1.0 and nop → 0.0. Debug via jobs/<job>/*/verifier/test-stdout.txt.
- Live-data graders (yfinance, 12306, web): a groundtruth-copy oracle may
  legitimately fail; then the bar is `oracle: n/a (live-data grader)` + nop
  producing a *sensible grader mismatch* (not a crash) + manual verification
  that the grader's live calls succeed from the container.
- After Dockerfile/init.sh edits: --force-build.

## Known pitfalls

- init.sh failures: healthcheck times out → trial errors. Read
  /var/run/toolathlon/preprocess.log via `docker exec` while the container is
  up, or temporarily run the image manually.
- Oracle solve.sh runs with /solution uploaded; typical implementation copies
  /solution/groundtruth_workspace/<outputs> to the /app paths the grader
  checks (read the grader for exact paths).
- LLM-judge graders read model config from the harness (utils model
  provider); wire TOOLATHLON_* env via [verifier].env with ${VAR} host
  interpolation, values in .env (self-hosted endpoint
  https://glm.analogyai.ai/v1, model qwen3.6-35b), run with --env-file .env.
- The agent-facing MCP tool surface is delivered on the mock track (see
  MOCK_TRACK.md): the mock servers are started per task with upstream's own
  scoping flags and reached from shell agents through `mcp-tool`, with
  unchanged tool names and schemas. Wiring the same servers into
  [[environment.mcp_servers]] for MCP-native agents is still to do.
- Mock-track tasks additionally strip the staged task subtree
  (preprocess sources, fixtures, groundtruth) from the image once init.sh
  has run it: upstream executes preprocess outside the container, so
  leaving e.g. calculate_groundtruth.py where the agent can read it would
  make the task easier than the official one.
